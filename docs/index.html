What is Tedi?

Tedi is a small, self-contained terminal text editor written from scratch in C (C11). It operates directly in raw terminal mode using ANSI/VT100 escape sequences, with no external library dependencies (no ncurses, no readline). It supports syntax highlighting for C and Python, incremental search, file save, and a color-scheme loader.

The entire editor lives in two source files:
  src/tedi.c — main editor loop, rendering, input, highlighting
  src/utils.c — filename extraction and true-color helpers

Features

Implemented (v0.0.1)

  • Raw terminal mode via termios — no external dependencies
  • Alternate screen buffer (editor does not trash your scrollback on exit)
  • Open a file from the command line: tedi myfile.c
  • Create a new file: tedi (prompted for filename on save)
  • Save file — Ctrl-S
  • Quit — Ctrl-Q (with unsaved-change guard; press ! to force)
  • Incremental search — Ctrl-F (arrow keys to navigate matches, Enter/Esc to exit)
  • Syntax highlighting:
    • C / C++ / headers (.c, .cpp, .h) — keywords, types, strings, numbers, single-line and multi-line comments
    • Python (.py) — keywords, built-in types, strings, numbers, single-line comments
  • Color scheme loader from plain-text .colorscheme files — Ctrl-T loads test.colorscheme
  • Default theme (ANSI 16-color): cyan comments, yellow keywords, magenta types, green strings, red numbers, blue search matches
  • Horizontal and vertical scrolling
  • Tab rendering as spaces (tab stop = 8)
  • Control character display (inverted caret notation, e.g. ^A)
  • Status bar: filename, modified flag, filetype, cursor position (row/total)
  • Message bar: timed status messages (TTL = 3 seconds)
  • Dirty-flag tracking (unsaved changes)
  • Home / End keys
  • Page Up / Page Down
  • Delete key
  • Backspace / Ctrl-H
  • Arrow key navigation (including wrapping across lines)
  • Insert newline (Enter)
  • Multi-line comment state carried across rows
  • Window resize detection via ioctl TIOCGWINSZ
  • True-color utility functions (setColorFG, setColorBG) in utils.c (available but not yet wired into the theme system)

Not Yet Implemented

  • Line numbers
  • Undo / Redo
  • Copy, Cut, Paste
  • Multiple open files / split views
  • Mouse support
  • Config file (~/.tedirc or similar)
  • Soft-wrap / hard-wrap
  • RGB / true-color theme fields (functions exist, not wired up)
  • Runtime colorscheme picker (only test.colorscheme is hard-coded to Ctrl-T)
  • Syntax highlighting for languages beyond C and Python
  • Shell integration (run a command, pipe output into buffer)
  • Plugin or extension system

Building & Running

  git clone <repo>
  cd tedi
  make          # release build: build/tedi
  make debug    # debug build:   build/tedi_debug
  make clean    # remove build/

  ./build/tedi              # open editor (new file)
  ./build/tedi myfile.c     # open existing file

Compiler: gcc (default) or any C11-compliant compiler. Override with CC=clang make.
Release flags: -O3 -march=native -s -Wall -Wextra -Wpedantic
Debug flags: -g -O0 -Wall -Wextra -Wpedantic

The DEBUG macro (set to 1 in source) controls whether die() prints the actual failing system call name or just prints "tedi".

Color Schemes

A .colorscheme file is a plain-text key=value file using ANSI color codes (integers). Load one at runtime with Ctrl-T (currently hard-coded to test.colorscheme).

Example: test.colorscheme

  comment=36
  keyword1=31
  keyword2=33
  keyword3=34
  string=32
  number=35
  match=43
  default_fg=37
  default_bg=40

ANSI Color Reference (foreground)

CodeColor
30Black
31Red
32Green
33Yellow
34Blue
35Magenta
36Cyan
37White

Note: The setColorFG and setColorBG functions in src/utils.c already support true-color (24-bit RGB via ESC[38;2;r;g;bm), but the editorColorScheme struct stores colors as plain integers (ANSI codes only). RGB support is a known TODO.

Known Bugs

  1. Ctrl-Q escape sequence off-by-one.
    write(STDOUT_FILENO, "\x1b[?1049l", 6) passes length 6 but the string \x1b[?1049l is 8 bytes. The last two bytes (4 and 9l... wait, specifically the 9l suffix) are not written, so the alternate screen buffer may not be properly exited on quit in some terminals. The correct length is 8. disableRawMode() already writes it correctly with length 8, so this only affects the force-quit path through Ctrl-Q + !.
  2. Raw mode flags: c_cflag |= ~(CS8) is wrong.
    Line 202: raw.c_cflag |= ~(CS8); should be raw.c_cflag |= CS8;. The bitwise-NOT of CS8 ORed in sets nearly all bits in c_cflag, which is unintended. In practice most terminals survive this because the original termios is restored on exit, but it is technically incorrect.
  3. Colorscheme name extraction strips extension incorrectly.
    getfilename() in src/utils.c searches from the start of the path for the last dot, not from after the last slash. A path like ../themes/test.colorscheme would result in a name starting from the slash before test, including the slash character, because name_start is set to the slash pointer (not slash + 1).
  4. Search wraps but does not indicate wrap-around.
    Incremental search silently cycles from the last match back to the first without any visual or status-bar notification that the search has wrapped.
  5. Status message bar is not cleared on quit-cancel.
    After pressing Ctrl-Q with unsaved changes and then declining with any key other than !, the warning message stays until it naturally expires (3 seconds) rather than being cleared immediately.
  6. Tab stop is fixed at 8.
    TAB_STOP is a compile-time constant. Files that use 2- or 4-space tabs will render with wider indentation than expected, with no runtime override.
  7. No window-resize signal handling.
    SIGWINCH is not caught. Resizing the terminal window while tedi is open will not update E.screenrows / E.screencols until the editor is restarted.
  8. Keyword3 is unused in syntax definitions.
    HL_KEYWORD_3 exists in the highlight enum and the color scheme struct, but no language in HLDB assigns any keyword to the third tier. It is dead code.
  9. Python multiline comment / docstring not highlighted.
    Python triple-quoted strings ("""...""" and '''...''') are not handled by the multiline comment system (both mcs and mce are set to empty strings in the Python HLDB entry), so they are highlighted as ordinary strings only until the closing delimiter appears on the same line.

Internals

Data Structures

struct editorConfig E (global singleton)
Holds cursor position (cx, cy, rx for rendered x), scroll offsets (rowoff, coloff), terminal dimensions, the row array, dirty flag, filename, status message, current syntax, original termios settings, and the active color theme.
typedef struct erow
Represents one line of text. Stores the raw character data (chars), a rendered version with tabs expanded (render), a per-character highlight array (hl), and an hl_open_comment flag that propagates multiline comment state to the next row.
struct editorSyntax
Defines a language: file extensions, keyword arrays (two tiers), single-line comment start token, multiline comment start/end tokens, and flags (HL_HL_NUMBERS, HL_HL_STRINGS).
struct editorColorScheme
Maps highlight categories to ANSI color codes (integers). Also stores a 16-character name. True-color is not yet stored here (see Known Bugs / Roadmap).
struct abuf (append buffer)
A simple growable byte buffer. All screen output is accumulated into one abuf per frame and written with a single write() call to avoid flickering.

Rendering Pipeline (one frame)

  editorRefreshScreen()
    editorScroll()             -- clamp rowoff/coloff to keep cursor visible
    abufAppend hide-cursor ESC
    abufAppend cursor-home ESC
    editorDrawRows()           -- render text lines with syntax colors
    editorDrawStatusBar()      -- filename | modified | filetype | row/total
    editorDrawMsgBar()         -- timed status message
    abufAppend cursor-position ESC
    abufAppend show-cursor ESC
    write(STDOUT_FILENO, ab.buf, ab.len)
    abufFree()

Input Loop

  while(1):
    editorRefreshScreen()
    editorProcessKeypress()
      editorReadkey()       -- reads raw bytes, decodes escape sequences
      dispatch on key       -- movement, edit, save, search, quit, etc.

Syntax Highlighting

Highlighting is computed lazily per row in editorUpdateSyntax() and stored in the erow.hl byte array. Each byte is an enum editorHighlight value. Multiline comment state is tracked via hl_open_comment on each row; when a row's open-comment state changes, the next row is re-highlighted recursively.

File I/O

Open: reads with getline(), strips \r\n, inserts rows.
Save: serializes all rows to a single string (editorRowsToStr()), then uses open(O_RDWR|O_CREAT) + ftruncate() + write(). This approach is atomic enough for a simple editor but does not use a temp-file swap strategy, so a crash mid-write could corrupt the file.
